# 오르락 인프라 + CI/CD 최종 매뉴얼 (SSAFY EC2 1대)

## 0) 구조

- 외부 오픈: **80/443만**
- 내부 전용: 8080(backend), 3306(DB), 6379(redis), 9000/9001(minio), 8081(jenkins)
- 접근 경로 (HTTPS 필수)
    - 앱 ↔ 서버 API: https://i14xxxx.p.ssafy.io/api/ → backend(8080)
    - 앱 ↔ 파일 저장소: https://i14xxxx.p.ssafy.io/minio/ → MinIO API(9000)
- 관리자 전용(권장: Basic Auth 또는 IP 제한)
    - https://i14xxxx.p.ssafy.io/jenkins/ → Jenkins(8081)
    - https://i14xxxx.p.ssafy.io/minio-console/ → MinIO Console(9001)

배포 방식(최소 리스크)

- 단일 backend 컨테이너 교체
- 배포 후 health 실패 → **이전 이미지로 자동 롤백**

※ 본 매뉴얼은 Nginx에서 /api를 rewrite로 제거하는 방식이므로,
SpringBoot의 context-path는 /api로 설정하지 않는다. (Actuator는 /actuator/health 유지)

## 6.2 Nginx 사이트 설정(HTTP 기본)

`/etc/nginx/sites-available/orak`

```
upstream backend_upstream { server 127.0.0.1:8080; keepalive 32; }
upstream jenkins_upstream { server 127.0.0.1:8081; keepalive 32; }
upstream minio_api_upstream { server 127.0.0.1:9000; keepalive 32; }
upstream minio_console_upstream { server 127.0.0.1:9001; keepalive 32; }

server {
  listen 80;
  server_name i14{팀ID}.p.ssafy.io;

  # 앱 API 통신
  location /api/ {
    rewrite ^/api/(.*) /$1 break;
    proxy_pass http://backend_upstream;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
  }

  # MinIO API
  location /minio/ {
    rewrite ^/minio/(.*) /$1 break;
    proxy_pass http://minio_api_upstream;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    client_max_body_size 200m;
  }

  # Jenkins (관리자)
	location /jenkins/ {
	  auth_basic "Jenkins Admin";
	  auth_basic_user_file /etc/nginx/.htpasswd-orak;
	
	  proxy_pass http://jenkins_upstream;
	  proxy_set_header Host $host;
	  proxy_set_header X-Real-IP $remote_addr;
	  proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
	  proxy_set_header X-Forwarded-Proto $scheme;
	
	  proxy_redirect off;
	}

  # MinIO Console (관리자)
	location /minio-console/ {
	  auth_basic "MinIO Console";
	  auth_basic_user_file /etc/nginx/.htpasswd-orak;
	
	  proxy_pass http://minio_console_upstream/;
	  proxy_set_header Host $host;
	  proxy_set_header X-Forwarded-Proto $scheme;
	  proxy_set_header X-Real-IP $remote_addr;
	  proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
	}

  location = / { return 404; }
}
```

적용:

```
sudo ln -s /etc/nginx/sites-available/orak /etc/nginx/sites-enabled/orak
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t
sudo systemctl restart nginx
```

※ certbot 실행 후, /etc/nginx/sites-available/orak 에 443(server { listen 443 ssl; }) 블록이 생성되면
/api, /minio, /jenkins, /minio-console location 설정이 443 블록에도 동일하게 존재하는지 반드시 확인한다.

```
sudo grep -n "listen 443" -n /etc/nginx/sites-available/orak
sudo grep -n "location /api/" -n /etc/nginx/sites-available/orak
sudo grep -n "location /minio/" -n /etc/nginx/sites-available/orak
sudo grep -n "location /jenkins/" -n /etc/nginx/sites-available/orak
sudo grep -n "location /minio-console/" -n /etc/nginx/sites-available/orak
```

## 7.2 체크/확인 블록 추가

```
# certbot 적용 후 nginx 설정 확인
sudo nginx -t

# HTTP로 접근 시 HTTPS로 리다이렉트 되는지 확인
```

# 14) Jenkinsfile (빌드→푸시→배포→헬스체크→자동 롤백)

> 이 Jenkinsfile은 “서버 내부에서 compose를 직접 조작”하는 방식이라 **SSH 필요 없음**.
> 
> 
> (SSAFY 1대 서버에서는 이게 가장 단순하고 안전)
> 

`Jenkinsfile`

```
pipeline {
  agent any

  environment {
    // 도커 이미지 이름
    IMAGE = "${DOCKERHUB_USER}/orak-backend"
    // 배포 디렉토리(ubuntu 홈 아래)
    DEPLOY_DIR = "/home/ubuntu/orak"
  }

  stages {
    stage('Checkout') {
      steps { checkout scm }
    }

    stage('Build Jar') {
      steps {
        sh "chmod +x gradlew"
        sh "./gradlew clean build -x test"
      }
    }

    stage('Docker Build') {
      steps {
        script {
          def shortHash = sh(script: "git rev-parse --short HEAD", returnStdout: true).trim()
          env.TAG = "${env.BUILD_NUMBER}-${shortHash}"
          sh "docker build -t ${IMAGE}:${env.TAG} ."
        }
      }
    }

    stage('Docker Push') {
      steps {
        script {
          docker.withRegistry('https://index.docker.io/v1/', 'dockerhub-cred') {
            sh "docker push ${IMAGE}:${env.TAG}"
            sh "docker tag ${IMAGE}:${env.TAG} ${IMAGE}:latest"
            sh "docker push ${IMAGE}:latest"
          }
        }
      }
    }

    stage('Deploy + HealthCheck + Rollback') {
      steps {
        script {
          // 이전 이미지 백업
          def prev = sh(script: "cd ${DEPLOY_DIR} && grep '^DOCKER_IMAGE=' .env | cut -d'=' -f2", returnStdout: true).trim()

          try {
            // 새 이미지로 교체 배포
            sh """
              set -e
              cd ${DEPLOY_DIR}
              sed -i 's|^DOCKER_IMAGE=.*|DOCKER_IMAGE=${IMAGE}:${env.TAG}|' .env
              docker compose pull backend
              docker compose up -d backend
            """

            // HealthCheck 재시도
            def ok = false
            for (int i=0; i<12; i++) {
              sleep 5
              def code = sh(script: "curl -s -o /dev/null -w '%{http_code}' http://127.0.0.1:8080/actuator/health || true", returnStdout: true).trim()
              if (code == "200") { ok = true; break }
            }

            if (!ok) {
              error("Health check failed after deploy")
            }

          } catch (e) {
            // 자동 롤백
            sh """
              set -e
              cd ${DEPLOY_DIR}
              echo "Rollback to: ${prev}"
              sed -i 's|^DOCKER_IMAGE=.*|DOCKER_IMAGE=${prev}|' .env
              docker compose pull backend
              docker compose up -d backend
            """
            throw e
          }
        }
      }
    }
  }

  post {
    always {
      // 디스크 안전장치(SSAFY 서버에서 중요)
      sh "docker image prune -f || true"
      cleanWs()
    }
  }
}
```

### Jenkinsfile이 동작하려면 필요한 것

- Jenkins에 환경변수 `DOCKERHUB_USER` 설정 필요
    
    Jenkins → Manage Jenkins → System → Global properties → Environment variables
    
    - `DOCKERHUB_USER = {도커허브계정}`

또는 Jenkinsfile 내 `IMAGE`를 그냥 하드코딩해도 됨:

```
IMAGE = "yourdockerhub/orak-backend"
```

## 1) Basic Auth 계정 파일 권한 (가끔 nginx가 못 읽는 경우)

보통은 괜찮지만, 만약 `/jenkins/` 접속 시 500/401 이상하게 나오면 권한을 확인해.

```
sudo ls -l /etc/nginx/.htpasswd-orak
sudo chown root:www-data /etc/nginx/.htpasswd-orak
sudo chmod 640 /etc/nginx/.htpasswd-orak
sudo nginx -t && sudo systemctl restart nginx
```

---

## 2) certbot 이후 “443 블록”에서 Basic Auth가 빠질 수 있음

너가 이미 443 블록에 `/jenkins`, `/minio-console` 확인을 넣어둬서 거의 완벽한데,

추가로 “Basic Auth 줄”도 있는지 확인하면 더 확실해.

```
sudo grep -n "auth_basic" /etc/nginx/sites-available/orak
sudo grep -n "auth_basic_user_file" /etc/nginx/sites-available/ora
```

(없으면 443 블록에 똑같이 넣어주면 됨)

---

## 3) Jenkinsfile `cleanWs()`는 “Workspace Cleanup 플러그인”이 있어야 함

너가 플러그인 목록에 `Workspace Cleanup` 넣어둬서 OK.

근데 만약 파이프라인에서 `cleanWs` 에러가 나면:

- 플러그인이 실제로 설치됐는지 확인하거나
- 임시로 `cleanWs()`를 주석처리하면 배포 자체는 계속 가능해.

# 시스템 구조 & 흐름도

## 1) 전체 아키텍처 한눈에 보기

```
[Android App]
   │  HTTPS (443) only
   ▼
[Nginx (Reverse Proxy + SSL 종료)]
   ├─ /api/*          ──▶  [SpringBoot Backend (Docker)]  (127.0.0.1:8080)
   ├─ /minio/*        ──▶  [MinIO API (Docker)]           (127.0.0.1:9000)
   ├─ /jenkins/*      ──▶  [Jenkins (Host)]               (127.0.0.1:8081)  + BasicAuth
   └─ /minio-console/ ──▶  [MinIO Console (Docker)]       (127.0.0.1:9001)  + BasicAuth

[Backend 내부 의존]
  Backend ──▶ MariaDB (Docker, 내부망) 3306
  Backend ──▶ Redis   (Docker, 내부망) 6379
  Backend ──▶ MinIO   (Docker, 내부망) 9000
```

### 핵심 포인트

- 외부(인터넷)에서 열려있는 포트는 **80/443만**
- DB/Redis/Backend/MinIO 포트는 **127.0.0.1 바인딩**이라 외부 직접 접근 불가
- 앱은 항상 `https://도메인/api/...` 로 호출 (Android HTTP 차단 대응)
- 관리자 페이지(`/jenkins`, `/minio-console`)는 **Basic Auth**로 보호

---

## 2) 앱 요청 흐름 (API 호출)

```
1) 앱이 API 호출: https://도메인/api/users/me

2) Nginx가 요청 수신(SSL 처리)
   - /api/ 경로 감지
   - rewrite로 /api 제거 → /users/me 로 변경

3) Nginx → Backend로 전달
   - http://127.0.0.1:8080/users/me

4) Backend 처리
   - 필요 시 MariaDB/Redis 조회
   - 결과 반환

5) Backend → Nginx → 앱으로 응답(HTTPS)
```

---

## 3) 앱 파일 업로드/다운로드 흐름 (MinIO)

```
1) 앱이 파일 업로드: https://도메인/minio/{bucket}/{object}

2) Nginx가 /minio/ 감지
   - rewrite로 /minio 제거 → /{bucket}/{object}

3) Nginx → MinIO API 전달
   - http://127.0.0.1:9000/{bucket}/{object}

4) MinIO 저장/조회 후 응답
```

> ※ Presigned URL을 쓸 경우, “서명에 들어가는 도메인/경로”가 맞아야 403이 안 나므로
> 
> 
> 백엔드에서 presigned 생성 시 외부 기준 주소를 `https://도메인/minio`로 맞추는 게 중요.
>

## 4) CI/CD 배포 흐름 (GitLab → Jenkins → Docker → 서버 반영)

```
[개발자]
  git push
    ▼
[GitLab Webhook]
    ▼
[Jenkins Pipeline 실행]
  1) 소스 체크아웃
  2) Gradle build (jar 생성)
  3) Docker image build
  4) DockerHub push (tag + latest)
  5) 서버 배포:
     - /home/ubuntu/orak/.env 의 DOCKER_IMAGE를 새 tag로 변경
     - docker compose pull backend
     - docker compose up -d backend
  6) Health Check:
     - http://127.0.0.1:8080/actuator/health
  7) 실패 시 자동 롤백:
     - 이전 DOCKER_IMAGE로 되돌리고 다시 up
```
