# 1. 앱 개요

## 1.1. 핵심 콘셉

### 1.1.1. 로그라인

사용자가 회원가입/로그인 후 Challenge(문제 세션) 을 만들고, 해당 세션에 Attempt(시도 영상) 을 업로드하면, 분석 결과를 바탕으로 실패 원인 1줄 / 위험 1개 / 다음 미션 1개를 제공하고, Challenge 종료 시 종합 요약을 제공하는 클라이밍 영상 분석 MVP

### 1.1.2. 핵심 재미

- 실패 순간/핵심 포인트를 빠르게 확인  
- Attempt가 쌓일수록 “이번 문제에서 반복되는 패턴”이 정리됨(종합 리포트)

### 1.1.3. 장르

클라이밍 영상 분석(퍼포먼스 코칭)

### 1.1.4. MVP 범위

- ✅ 계정(아이디/비밀번호/닉네임) 회원가입/로그인 (users)
- ✅ Challenge 생성/진행/종료 + 홀드 데이터 저장(선택) (challenges.holds_json)
- ✅ Attempt 생성(번호 자동) + 업로드 상태/분석 상태 관리 (attempts, challenge_attempt_counters)
- ✅ 영상 저장 메타 + MinIO 참조 (attempt_video)
- ✅ Attempt 결과(3줄) (attempt_feedbacks)
- ✅ Attempt 상세 지표 (attempt_metrics)
- ✅ Challenge 종료 후 종합 요약 (challenge_summaries)
- ✅ 모든 주요 엔티티는 soft delete(deleted_at) 기반 운영

## 1.2. 타깃 오디언스

초보~중수(피드백 필요), 중수 이상(반복 실패/크럭스 정리)

## 1.3. 톤앤매너

- “코치가 핵심만 말해주는 느낌”
- 기본 화면은 항상 3개만:
  - 실패 원인 1줄
  - 위험 1개
  - 다음 미션 1개
- 지표/로그는 “더보기”

# 2. 핵심 사용자 경험 (Core UX)

## 2.1. 기본 규칙

- Challenge = 문제 세션 1개 (challenges)
- Attempt = 영상 1개 + 분석 리포트 1개 (attempts + attempt_video + attempt_feedbacks + attempt_metrics)
- 한 세션 안에서 여러 번 시도 가능
- Attempt 번호는 challenge 단위로 자동 증가 (challenge_attempt_counters 기반)
- 세션 종료 시 종합 요약 생성/갱신 (challenge_summaries)
- 삭제는 전부 물리 삭제가 아니라 soft delete(deleted_at) 로 처리

## 2.2. 사용자 흐름

### Step 0. 회원가입 / 로그인

입력: username / password / nickname  
저장: users  

참고: 신체 정보는 MVP에서 사용하지 않지만, 테이블은 유지 (user_profiles는 optional/미사용)

### Step 1. Challenge 생성 (문제 세션 시작)

입력값:

- gym_name (선택)
- problem_color (필수)
- grade_label (선택)
- holds_json (선택)

사용자가 홀드를 지정하거나(추후), 최소 MVP에서는 비워도 됨

저장:

- challenge_status = ACTIVE
- started_at 기록(앱에서 저장)
- 생성 시점에 attempt 카운터 row 자동 생성(트리거)
- challenge_attempt_counters.next_attempt_no = 0

### Step 2. Attempt 추가 (영상 업로드 시작)

과거 촬영 영상(mp4) 선택 가능  

Attempt 생성 시 번호 자동 발급  
attempt_no는 challenge_attempt_counters로 발급  

Attempt 상태 흐름(DDL 확정):

- UPLOADING
- 업로드 실패 시: UPLOAD_FAILED
- 업로드 성공 후 분석 대기/진행: PROCESSING
- 분석 실패 시: ANALYSIS_FAILED
- 분석 성공 시: DONE

영상 저장(DDL 기준: attempt_video 1:1):

attempt_video에 MinIO 참조 메타 저장  

- bucket
- object_key
- content_type
- file_size
- etag

업로드 완료 시:

- attempt_video.is_uploaded = 1
- attempt_video.uploaded_at 기록

### Step 3. Attempt 결과 화면

#### 기본 화면(항상 노출)

- 실패 원인 1줄: attempt_feedbacks.failure_reason
- 위험 1개: attempt_feedbacks.risk_alert
- 다음 미션 1개: attempt_feedbacks.next_mission

(추적용 메타)

- model_version
- prompt_version
- generated_at

#### 상세보기 버튼 클릭 시(지표)

- 중심 안정 비율: attempt_metrics.center_stability_ratio
- 크럭스 홀드 번호: attempt_metrics.crux_hold_no
- 크럭스 구간 시간: attempt_metrics.crux_duration_ms
- 위험 이벤트 수: attempt_metrics.danger_event_count
- 최고 도달 홀드: attempts.max_hold_no
- 영상 길이(ms): attempts.duration_ms

### Step 4. Challenge 종료

사용자가 “세션 종료” 버튼 클릭  

저장:

- challenge_status = CLOSED
- ended_at 기록
- (선택) challenge_result는 성공/실패/미정으로 남길 수 있음  
- MVP에서 자동 판정이 없으면 UNKNOWN 유지 가능

### Step 5. Challenge 종합 리포트 화면

데이터 출처: challenge_summaries (Challenge 1개당 1개)

기본 출력:

- 평균 중심 안정 비율: average_center_stability_ratio
- 가장 많이 등장한 크럭스 홀드: most_crux_hold_no
- 가장 긴 크럭스 구간 시간(최댓값): max_crux_duration_ms
- 최종 종합 코멘트: final_comment

확장 보기:

Attempt별 비교(앱에서 attempts + metrics + feedbacks 조합 조회)

# 3. 분석 로직 (MVP 범위)

## 3.1. 입력

- mp4 영상
- 문제 색상(problem_color)

## 3.2. 분석 요소

MVP에서는 4가지 축:

1. 실패 시점 탐지
2. 최고 도달 홀드 계산
3. 중심 안정 비율 계산
4. 크럭스 구간 탐지

## 3.3. Attempt 단위 산출값

### attempts

- duration_ms
- max_hold_no
- attempt_result
- analysis_started_at, analysis_ended_at
- attempt_status

### attempt_metrics

- center_stability_ratio
- crux_hold_no
- crux_duration_ms
- danger_event_count

### attempt_feedbacks

- failure_reason
- risk_alert
- next_mission
- (+추적) model_version, prompt_version, generated_at

## 3.4. Challenge 종료 시 집계 로직

대상: 해당 challenge_id의 attempts + attempt_metrics + attempt_feedbacks

집계:

- 평균 중심 안정 비율 → average_center_stability_ratio
- 가장 많이 등장한 크럭스 홀드 → most_crux_hold_no
- 가장 긴 크럭스 구간 시간(Attempt들의 crux_duration_ms 최댓값) → max_crux_duration_ms
- 반복 실패 원인 기반 종합 코멘트 생성 → final_comment

저장:

challenge_summaries에 생성 또는 업데이트(UPSERT)

# 4. 데이터 흐름 (End-to-End)

## 4.1. 업로드 → 분석

- Challenge 내 attempt_no 발급(challenge_attempt_counters)
- attempts 생성(상태 UPLOADING)
- attempt_video 생성(초기 is_uploaded=0)
- MinIO 업로드 성공 → attempt_video 업데이트(is_uploaded=1, 메타 저장)
- attempts.attempt_status = PROCESSING, analysis_started_at 기록
- AI 워커 분석 수행
- 결과 저장
  - attempts 업데이트(attempt_result, duration_ms, max_hold_no, analysis_ended_at)
  - attempt_metrics insert
  - attempt_feedbacks insert
- attempts.attempt_status = DONE

(실패 시)

- 업로드 실패 → UPLOAD_FAILED
- 분석 실패 → ANALYSIS_FAILED

## 4.2. 세션 종료 → 종합 리포트

- Challenge 종료(CLOSED, ended_at)
- challenge_id 기준 attempts/metrics/feedbacks 조회
- 집계
- challenge_summaries 생성/업데이트

# 5. UI 구조 요약

## 홈

- 진행 중 Challenge 목록(ACTIVE)
- 종료된 Challenge 목록(CLOSED)

## Challenge 상세

- Attempt 리스트(번호 기반)
- 영상 업로드 버튼
- 세션 종료 버튼

## Attempt 결과 화면

- 기본 3줄(피드백)
- 상세보기(지표)

## Challenge 종합 화면

- 평균 안정성 / 대표 크럭스 / 최장 크럭스 시간 / 종합 코멘트
- Attempt별 비교(확장)

# 6. 1차 MVP 목표 정의

- 자동 분석이 실제로 유의미한 “3줄 피드백”을 만들 수 있는지 검증
- 영상 업로드 → MinIO 저장 → 워커 분석 → DB 저장 → 화면 출력 흐름 검증
- 세션 단위 집계(challenge_summaries)가 의미 있는 인사이트를 만드는지 검증
- 신체 정보 없이도 충분히 가치가 있는지 확인하는 단계
- user_profiles는 테이블만 유지(미사용)

# 7. MVP 개발 우선순위

1. 회원/로그인 (users)
2. Challenge 생성/목록 (challenges)
3. Challenge 생성 시 카운터 생성 확인(트리거) (challenge_attempt_counters)
4. Attempt 생성 + attempt_no 발급 + 업로드 상태 (attempts)
5. MinIO 업로드 + 메타 저장 (attempt_video)
6. 워커 분석 연결 + 상태 전이/시간 기록 (attempts.analysis_*, status)
7. Attempt 결과 화면(3줄) (attempt_feedbacks)
8. 상세보기 지표 (attempt_metrics)
9. Challenge 종료 + 종합 리포트 upsert (challenge_summaries)
