# DDGo 포팅 매뉴얼

## 1. 프로젝트 개요

DDGo는 클라이밍 도전 과제 관리, 시도 영상 업로드, AI 분석 결과 확인, 커뮤니티, 웨어러블 연동을 제공하는 서비스입니다.

현재 저장소는 단일 애플리케이션이 아니라 아래 4개 축으로 나뉘어 있습니다.

- `DDGo`
  - Spring Boot 백엔드 서버
  - MariaDB / Redis / MinIO 연동
  - 인증, 챌린지, 시도, 커뮤니티, 암장 API 제공
- `DDgo_AI_Server`
  - FastAPI + MuJoCo 기반 AI 분석 서버
  - 홀드 좌표, 포즈 시퀀스, 사용자 신체 정보 기반 분석 수행
- `DDGo_android`
  - Android 모바일 앱 + Wear OS 앱
  - 백엔드 API 호출, AI 서버 호출, 웨어러블 데이터 동기화 담당
- `DDgo_AI_yolo`
  - 온디바이스 YOLO/TFLite 포팅 참고용 리포지토리
  - 운영 필수 모듈이 아니라 참고 자산에 가깝습니다

중요:

- 현재 구조상 백엔드가 AI 서버를 직접 호출하지 않습니다.
- 모바일 앱이 백엔드와 AI 서버를 각각 호출합니다.
- 영상 원본은 백엔드가 발급한 Presigned URL을 통해 MinIO로 직접 업로드됩니다.

## 5. 모듈별 상세 역할

### 5.1 `DDGo` 백엔드

주요 도메인:

- `users`
  - 회원가입 / 로그인 / 토큰 재발급 / 로그아웃
  - 카카오 / 구글 소셜 로그인
  - 비밀번호 재설정 메일
- `challenges`
  - 챌린지 생성 / 상태 조회 / 목록 조회 / 종료 / 종합 요약
- `attempts`
  - 시도 생성 / 종료 / 상세 조회
  - 영상 업로드용 Presigned URL 발급
- `community`
  - 게시글 / 댓글 / 좋아요
  - 커뮤니티 영상 업로드 Presigned URL 발급
- `gyms`
  - 암장 매핑 / 난이도 조회

중요:

- 실제 구현된 소셜 로그인 제공자는 `KAKAO`, `GOOGLE` 두 종류입니다.
- DB 스키마의 일부 enum에 `NAVER`가 남아 있지만, 현재 서버/앱 코드에는 네이버 로그인 구현이 없습니다.

주요 공개 엔드포인트:

- `GET /actuator/health`
- `GET /swagger-ui/index.html`
- `GET /v3/api-docs`
- `POST /v1/users/register`
- `POST /v1/users/login`
- `POST /v1/users/social/login`
- `POST /v1/users/refresh`
- `POST /v1/users/password/reset/request`
- `POST /v1/users/password/reset/confirm`
- `POST /v1/attempts/{attemptId}/video-url`


### 5.2 `DDgo_AI_Server` AI 서버

AI 서버는 FastAPI 기반이며 아래 두 종류의 버전 경로를 제공합니다.

- `/api/v1`
  - 배치 분석
  - 실시간 세션 분석
- `/api/v2`
  - gzip 요청을 고려한 배치 분석 전용

대표 엔드포인트:

- `GET /health`
- `GET /docs`
- `GET /openapi.json`
- `POST /api/v1/mujoco-complete/analyze/fast`
- `POST /api/v1/mujoco-complete/analyze/physics`
- `POST /api/v1/mujoco-complete/session/start`
- `POST /api/v1/mujoco-complete/session/{session_id}/pose-chunks`
- `POST /api/v1/mujoco-complete/session/{session_id}/context`
- `POST /api/v1/mujoco-complete/session/{session_id}/finalize`
- `DELETE /api/v1/mujoco-complete/session/{session_id}`
- `POST /api/v2/mujoco-complete/analyze/fast`
- `POST /api/v2/mujoco-complete/analyze/physics`

운영 배포 시:

- Dockerfile이 `uvicorn app.main:app --root-path /ai` 로 실행됩니다.
- 외부 공개 URL은 일반적으로 `/ai/*` 형태를 사용합니다.
- 로컬 직접 실행 시에는 `http://localhost:8000/health` 처럼 prefix 없이 접근해도 됩니다.

### 5.3 `DDGo_android` 모바일 + 워치 앱

구성 모듈:

- `:app`
  - Android 휴대폰 앱
- `:wear`
  - Wear OS 앱
- `:core-shared`
  - 공통 직렬화 / 공유 모델

모바일 앱 특징:

- 기본 백엔드 URL은 `https://j14d204.p.ssafy.io/api/`
- 기본 AI 서버 URL은 `https://j14d204.p.ssafy.io/ai/`
- 카카오 로그인과 구글 로그인을 모두 지원
- MediaPipe / TFLite 기반 온디바이스 전처리와 FastAPI AI 서버 호출을 함께 사용
- MinIO Presigned URL 기반 영상 업로드 사용

워치 앱 특징:

- 휴대폰 앱과 동일한 `applicationId = com.ddgo.app` 을 사용합니다.
- 녹화 상태 동기화, 운동 상태 표시, 경고 진동을 담당합니다.
- `RecordingStateListenerService`, `WatchExerciseService` 중심 구조입니다.

### 5.4 `DDgo_AI_yolo`

이 디렉터리는 현재 운영 필수 모듈이 아닙니다.

용도:

- YOLOv8 TFLite 모델 교체 가이드
- Android 프로젝트에 YOLO 검출 로직을 포팅하는 참고 문서

즉, 서버 이관 시 반드시 배포해야 하는 것은 `DDGo`, `DDgo_AI_Server`, `DDGo_android` 쪽입니다.

```env
MINIO_ACCESS_KEY=minioadmin
MINIO_SECRET_KEY=minioadmin
MINIO_BUCKET=ddgo_videos

GOOGLE_CLIENT_ID=your-google-web-client-id
SOCIAL_HTTP_CONNECT_TIMEOUT_MS=3000
SOCIAL_HTTP_READ_TIMEOUT_MS=3000

MAIL_HOST=smtp.example.com
MAIL_PORT=587
MAIL_USERNAME=mail-user
MAIL_PASSWORD=mail-password

CHALLENGE_STALE_ACTIVE_AUTO_CLOSE_ENABLED=true
CHALLENGE_STALE_ACTIVE_AUTO_CLOSE_STALE_AFTER_HOURS=6
CHALLENGE_STALE_ACTIVE_AUTO_CLOSE_INTERVAL_MS=3600000

```

참고:

- 로컬 `docker-compose.yml` 은 MariaDB / Redis / MinIO 기본 값을 상당수 고정하고 있습니다.
- JVM 로컬 실행 시에는 위 값을 직접 환경 변수로 넣어야 합니다.
- `me.paulschwarz:spring-dotenv` 가 포함되어 있어, 로컬 개발 시 `DDGo/.env` 파일로도 값을 주입할 수 있습니다.
- `MINIO_PUBLIC_URL` 을 비워 두면 `application.yml` 에서 `MINIO_URL` 값을 기본값으로 재사용합니다.
- `PASSWORD_RESET_URL` 기본값은 `http://localhost:3000/reset-password` 이므로 운영 배포 시에는 반드시 실제 도메인으로 덮어써야 합니다.

### 7.4 Android `local.properties`

`DDGo_android/app/build.gradle.kts` 기준으로 아래 값이 필요합니다.

```properties
sdk.dir=C\:\\Users\\<user>\\AppData\\Local\\Android\\Sdk

api.base.url=https://your-domain/api/
ai.server.base.url=https://your-domain/ai/

kakao.rest.api.key=your-kakao-rest-api-key
kakao.native.app.key=your-kakao-native-app-key
google.web.client.id=your-google-web-client-id
```

주의:

- 이 파일이 없으면 앱은 기본값으로 `https://j14d204.p.ssafy.io/api/`, `https://j14d204.p.ssafy.io/ai/` 를 사용합니다.
- 즉, 로컬에서 테스트하려면 반드시 `api.base.url`, `ai.server.base.url` 를 원하는 서버 주소로 덮어써야 합니다.
- 현재 `AndroidManifest.xml` 에 `usesCleartextTraffic="false"` 가 설정되어 있으므로, 휴대폰 앱은 기본적으로 HTTP 평문 서버에 바로 붙지 않습니다.
- 로컬 HTTP 서버를 쓰려면 HTTPS 프록시를 쓰거나 디버그용 network security 설정을 별도로 추가해야 합니다.

### 9.1 Nginx 라우팅 요구사항

이 저장소에는 실제 운영 Nginx 설정 파일이 포함되어 있지 않으므로, 아래 동작을 만족하도록 직접 구성해야 합니다.

필수 요구사항:

- `/api/*` -> Spring Boot backend
- `/ai/*` -> FastAPI AI server
- `/.well-known/assetlinks.json` -> Android App Links 정적 파일
- 필요 시 `/minio` 또는 MinIO Console 관리 경로 별도 공개

예시 스케치:

```nginx
server {
    listen 443 ssl;
    server_name your-domain;

    location /api/ {
        rewrite ^/api/(.*)$ /$1 break;
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /ai/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /.well-known/assetlinks.json {
        root /opt/ddgo/nginx/html;
        default_type application/json;
    }
}
```

주의:

- AI 서버는 `--root-path /ai` 로 구동되므로, 운영에서는 `/ai` prefix가 유지되도록 노출하는 쪽이 안전합니다.

- 운영 시연이면 HTTPS, `/api`, `/ai`, App Links, `/.well-known/assetlinks.json` 이 모두 정상이어야 합니다.

### 12.2 메인 시나리오: 영상 업로드 기반 챌린지 분석

1. 앱 실행 후 `Splash` 를 지나 인증 화면으로 진입합니다.
2. 인증 화면 하단 `로그인` 을 눌러 이메일 로그인 화면으로 이동합니다.
3. `demo5@ddgo.local / Demo1234!` 를 입력하고 `로그인` 을 눌러 메인 화면으로 진입합니다.
4. 하단 탭 기본 진입 화면이 `캘린더` 인지 확인한 뒤, 하단 중앙 원형 FAB `클라이밍` 을 누릅니다.
5. 팝업 메뉴에서 상단 `영상 업로드` 를 눌러 업로드 플로우를 시작합니다.
6. 첫 화면 하단의 흰색 버튼 `동영상 선택` 을 눌러 첫 시도 영상을 고릅니다.
7. `클라이밍 기록` 1단계에서 상단 검색창에 암장명을 입력하거나, 검색창 오른쪽 `현재 위치 검색` 아이콘을 눌러 암장을 조회합니다.
8. 결과 카드 중 원하는 암장을 눌러 `선택됨` 상태를 만든 뒤, 화면 하단 `다음` 버튼을 누릅니다.
9. 2단계 `문제 레벨` 화면에서 원하는 난이도 카드를 선택하고 하단 `다음` 을 누릅니다.
10. 3단계 홀드 색상 선택 화면에서 문제 색상을 고르고 하단 `다음` 을 누릅니다.
11. `홀드 확인` 화면에서 AI가 놓친 홀드가 있으면 프레임을 직접 터치해 선택/해제합니다.
12. 추가 시도 영상을 더 붙여 시연하고 싶으면 `추가 시도 영상 업로드` 를 진행하고, 아니면 다음 단계로 이동합니다.
13. 시작 홀드 선택 화면에서는 시작 홀드를 터치한 뒤 `다음 단계로 이동하기` 를 누릅니다.
14. 목표 홀드 선택 화면에서는 목표 홀드를 터치한 뒤 `선택 완료` 를 누릅니다.
15. 로딩 화면이 끝나면 시도별 결과가 먼저 나오고, 하단 CTA로 `다음 시도 분석 결과 보기` 또는 `챌린지 종합 분석 결과 보기` 를 이어서 확인합니다.
16. 최종 분석 화면에서 `홈으로 이동` 을 눌러 메인으로 돌아갑니다.
17. 하단 탭 `분석` 으로 이동해 최근 기록 목록이 보이는지 확인하고, 챌린지 카드를 눌러 `시도별 성장` 과 시도 상세 분석까지 열어 시연합니다.

### 12.3 보조 시나리오: 실시간 기록 + 워치 연동

1. 메인 화면 하단 중앙 FAB `클라이밍` 을 누른 뒤 팝업 메뉴에서 `실시간 기록` 을 누릅니다.
2. 실시간 기록 진입 직후 워치 앱이 실행되고 동기화 상태가 붙는지 확인합니다.
3. 필요 시 먼저 암장 / 난이도 / 홀드 색상 정보를 선택합니다.
4. 카메라 권한 요청이 뜨면 허용하고, 중앙 CTA `촬영 시작` 을 눌러 기록을 시작합니다.
5. 시연 중 워치에 녹화 상태가 동기화되는지 확인합니다.
6. 종료 시점에 `촬영 종료` 를 눌러 기록을 마칩니다.
7. 이후 흐름은 실시간 업로드 경로를 따라 홀드 선택 -> 분석 로딩 -> 결과 화면으로 이어지는지 확인합니다.

### 12.4 보조 시나리오: 비밀번호 재설정 딥링크

1. 로그인 화면에서 비밀번호 재설정 진입점을 눌러 재설정 메일 발송을 요청합니다.
2. 메일 본문의 `https://<도메인>/reset-password?...` 링크를 모바일 기기에서 엽니다.
3. 브라우저가 아니라 DDGo 앱으로 직접 열리는지 확인합니다.
4. 앱 내부 `PasswordResetScreen` 으로 진입해 새 비밀번호 저장까지 완료합니다.

## 14. 트러블슈팅

### 14.1 테이블이 없다는 오류

원인:

- `spring.jpa.hibernate.ddl-auto: none`

해결:

- 반드시 `DDGo.sql` 을 먼저 적용하고 서버를 기동합니다.

### 14.2 SQL 적용 중 한글 깨짐

원인:

- PowerShell 파이프 입력 시 인코딩 손상 가능

해결:

- `docker cp` 로 SQL 파일을 컨테이너에 넣고 `< file.sql` 형태로 실행합니다.

### 14.3 Android 앱이 로컬 서버 대신 운영 서버로 붙는 문제

원인:

- `local.properties` 의 `api.base.url`, `ai.server.base.url` 누락

해결:

- `DDGo_android/local.properties` 에 값을 직접 명시합니다.

### 14.4 Android 앱이 HTTP 로컬 서버에 접속하지 못하는 문제

원인:

- `usesCleartextTraffic="false"`

해결:

- HTTPS 프록시를 사용하거나 디버그용 network security 설정을 추가합니다.

### 14.5 비밀번호 재설정 링크가 브라우저로만 열리고 앱으로 열리지 않는 문제

원인:

- App Links 도메인, SHA-256, `assetlinks.json`, 매니페스트 host 불일치

해결:

- `AndroidManifest.xml`
- `assetlinks.json`
- 배포 도메인
- 서명 키 fingerprint

네 가지를 함께 맞춥니다.

### 14.6 네이버 로그인이 왜 안 보이는지 혼동되는 문제

원인:

- DB enum에는 `NAVER`가 남아 있지만 현재 구현은 `KAKAO`, `GOOGLE` 만 존재

해결:

- 현재 포팅 범위에서는 네이버 로그인을 제외하고 인수인계합니다.

### 14.7 AI 서버 경로가 `/health` 인지 `/ai/health` 인지 헷갈리는 문제

원인:

- 로컬 직접 실행과 운영 프록시 경로가 다름

정리:

- 로컬 직접 실행: `/health`
- 운영 공개 URL: `/ai/health`

### 14.8 MinIO 업로드가 실패하는 문제

원인:

- Presigned URL에 추가 인증 헤더를 붙였거나
- `MINIO_PUBLIC_URL` 과 외부 공개 주소가 맞지 않음

해결:

- Presigned URL 업로드 시 별도 Authorization 헤더를 넣지 않습니다.
- 외부 공개 주소를 기준으로 `MINIO_PUBLIC_URL` 을 맞춥니다.

### 14.9 워치 동기화가 안 되는 문제

원인:

- 휴대폰 앱과 워치 앱 중 하나만 설치
- 패키지명 불일치
- Wearable 서비스 연결 문제

해결:

- 휴대폰과 워치 모두 `com.ddgo.app` 패키지로 설치
- Wear OS 연결 상태 확인
- 양쪽 앱 재설치 후 동기화 재시도

## 15. 특이사항

현재 저장소 기준으로 꼭 기억할 점:
