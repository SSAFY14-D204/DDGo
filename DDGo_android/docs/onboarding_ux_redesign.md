# DDGo 온보딩 UX/UI 재설계안

작성 기준일: 2026-03-24  
참고 피그마 섹션: `ThoPBdnoCD4obdFhL9Nozr` / `747:1256 (ONBOARDING)`

## 1. 목표

DDGo 온보딩의 목적은 "정보를 많이 받는 것"이 아니라, 사용자가 최대한 빠르게 앱의 핵심 가치에 진입하도록 돕는 것이다.

DDGo의 첫 가치 경험은 아래 중 하나여야 한다.

- 내 실력과 신체 특성에 맞는 시작점이 보인다
- 자주 가는 암장을 기준으로 기록/분석 흐름이 연결된다
- 첫 분석 또는 첫 기록까지 가는 다음 행동이 매우 명확하다

즉, 온보딩은 `질문 플로우`가 아니라 `첫 등반 경험으로 진입시키는 가벼운 개인화 레이어`로 설계해야 한다.

## 2. 피그마 섹션에서 확인한 패턴

섹션 전체를 보면 다음 4개 묶음으로 정리된다.

- 질문형 온보딩: 성별, 나이, 키, 몸무게, 운동 목표, 운동 요일, 운동 경험 등 한 화면 한 결정 구조
- 개인화 결과 제시: 선택 결과를 바탕으로 맞춤 루틴, 추천 이유, 성장 기대치 제시
- 신뢰 강화: 논문/기관 근거, 그래프, 회복도, 프로그램 예시 등 설명형 화면
- 전환 유도: 할인/프로 결제, 후기, 비교표, 혜택 강조

섹션의 장점은 명확하다.

- 질문이 단순해서 답변 피로가 낮다
- 각 선택 직후 피드백이 들어와 사용자 반응이 좋다
- 결과 카드와 CTA가 강해서 다음 행동이 선명하다

반대로 DDGo에 그대로 가져오면 아쉬운 점도 있다.

- 질문 수가 많아 클라이밍 앱 첫 진입 치고 길다
- 헬스/식단 중심 문법이라 DDGo의 핵심 가치와 맞지 않는다
- 위치 권한, 결제, 설명형 슬라이드가 이른 시점에 나오면 첫 가치 체감이 늦어진다
- 몸무게/키/연도 등을 각각 한 화면씩 분리하면 입력 마찰이 커진다

## 3. 최신 UX/UI 기준으로 정리한 원칙

2026-03-24 기준으로 공식 가이드와 2025 벤치마크를 보면, 초기 온보딩은 아래 원칙이 가장 중요하다.

- 첫 세션에서는 `필수 정보만` 받고 나머지는 점진적으로 받는다
- 권한 요청은 실제 기능을 쓰기 직전에 맥락 안에서 요청한다
- 사용자 선택값은 바로 홈/추천/기록 화면 개인화에 반영되어야 한다
- 결제 전환은 첫 가치 체감 이후로 미루는 편이 자연스럽다
- 온보딩은 설명보다 `예상 결과`를 먼저 보여줄수록 강하다

DDGo에는 이를 아래처럼 적용하는 것이 적절하다.

- `암장`, `현재 실력`, `개선 목표`, `키/윙스팬`은 초기에 유효
- `카메라 권한`, `알림 권한`, `심화 설문`, `프로 전환`은 후순위
- `체중`, `성별`은 필요한 경우 받되 입력 부담을 낮춰야 한다

## 4. DDGo 권장 온보딩 플로우

권장 구조는 `초기 온보딩 5화면 + 기능 진입 후 점진적 온보딩`이다.

### Screen 1. Hero / 가치 제안

목적:
사용자가 "이 앱이 나한테 어떤 도움을 주는지"를 3초 안에 이해하게 만든다.

핵심 카피 예시:

- 헤드라인: `내 몸과 무브에 맞는 클라이밍 시작점`
- 서브카피: `암장 기록, 자세 분석, 성장 추적까지 DDGo가 한 번에 이어줄게요`
- CTA: `내 등반 시작하기`
- 보조 액션: `나중에 할게요`

구성:

- 상단 여백 넉넉한 1열 레이아웃
- 중앙에는 실사형 클라이머 컷아웃 또는 홀드가 보이는 월 비주얼
- 하단에 강한 풀폭 CTA

설계 이유:

- 피그마 섹션의 큰 헤드라인 구조는 유지하되, 헬스 루틴 대신 DDGo의 핵심 가치로 교체
- 기능 설명 나열보다 "나에게 맞는 시작점"이라는 약속이 더 강함

### Screen 2. Home Gym 선택

목적:
기록, 추천, 커뮤니티의 기본 맥락이 되는 대표 암장을 설정한다.

핵심 요소:

- 검색 필드: `암장 이름으로 찾기`
- 빠른 액션 칩: `현재 위치로 찾기`
- 최근/가까운 암장 카드 리스트
- 보조 액션: `나중에 선택`

마이크로 UX:

- 위치 권한은 `현재 위치로 찾기` 탭 시에만 요청
- 권한 요청 전 한 줄 설명 배너 제공
- 선택 완료 시 하단 CTA 문구를 `이 암장에서 시작하기`로 변경

설계 이유:

- DDGo는 장소 맥락이 매우 중요하므로 첫 개인화 값으로 적합
- Android 공식 가이드처럼 권한은 기능 문맥 안에서 요청하는 편이 좋음

### Screen 3. 현재 클라이밍 프로필

목적:
홈 피드와 추천 난이도, 첫 액션 카드를 개인화한다.

한 화면 안에 두 블록으로 구성:

- 현재 레벨
  - `입문 막 시작`
  - `V0-V2 / 쉬운 문제 위주`
  - `V3-V5 / 중급 도전 중`
  - `프로젝트 중심`
- 주로 타는 스타일
  - `볼더링`
  - `리드/탑로프`
  - `둘 다`

UI 형태:

- 큰 선택 카드 또는 2열 카드 그리드
- 선택 시 틴트 배경 + 2px 라인 + 미세한 상승 모션

설계 이유:

- 피그마 섹션의 "한 화면 한 판단" 장점을 유지하면서도, DDGo에 진짜 필요한 정보만 압축
- 운동 요일, 세트 기록, 식단 질문은 초기 진입 가치와 직접적 연관이 적음

### Screen 4. 개선 목표 선택

목적:
첫 홈 화면과 추천 액션을 목표 기반으로 정렬한다.

추천 목표:

- `완등률 올리기`
- `다이노/리치 개선`
- `지구력 키우기`
- `부상 없이 오래 타기`
- `기록 습관 만들기`

UI 형태:

- 피그마의 목표 선택 화면처럼 큰 단일 선택 카드
- 선택 후 상단에 짧은 피드백 카피 노출

피드백 카피 예시:

- `좋아요. 그 목표에 맞춰 첫 추천 루트를 잡아드릴게요`
- `리치가 중요하네요. 윙스팬 정보가 있으면 더 정확해져요`

설계 이유:

- 목표를 먼저 잡아두면 결과 카드와 첫 액션 CTA를 더 설득력 있게 만들 수 있음

### Screen 5. 신체 프로필 입력

목적:
분석과 추천 정밀도를 높이되, 입력 피로는 최소화한다.

권장 입력 항목:

- 성별
- 키
- 윙스팬
- 체중: 선택 입력 또는 하단 `나중에 입력` 제공

권장 레이아웃:

- 개별 화면 분리 대신 `한 화면 폼`으로 묶기
- 숫자 입력 필드는 카드형 2열 또는 1열 그룹
- 키보드가 올라와도 CTA가 고정되게 구성

윙스팬 UX 제안:

- 보조 텍스트: `모르면 나중에 입력 가능`
- 보조 액션: `쉽게 재는 법 보기`
- 미입력 시 기본값을 `키와 동일`로 가정할 수 있게 안내

설계 이유:

- 피그마처럼 키/몸무게를 각각 나누면 이탈 확률이 커짐
- DDGo에서는 윙스팬이 중요한 대신, 대부분 즉시 알지 못할 가능성이 높아 강제 입력은 좋지 않음

### Screen 6. 개인화 결과 카드

목적:
사용자에게 "이미 내 앱이 되었다"는 감각을 준 뒤 첫 행동으로 보낸다.

카드 예시:

- 타이틀: `OO님에게 맞는 시작 프로필이 준비됐어요`
- 요약 정보:
  - `주 암장: 더클라임 신림`
  - `현재 포지션: 볼더링 입문`
  - `집중 포인트: 리치 활용 / 완등률`
- 추천 액션:
  - `첫 등반 기록 시작`
  - `내 신체 기준 저장 완료`
  - `암장별 추천 문제 보기`

메인 CTA:

- `첫 기록 시작하기`

보조 CTA:

- `홈 먼저 둘러보기`

설계 이유:

- 피그마 섹션의 "루틴이 준비됐어요" 카드 구조는 매우 좋다
- DDGo에서는 루틴 대신 `내 등반 시작 카드`로 바꾸는 것이 자연스럽다

## 5. 기능 진입 후 점진적 온보딩

처음부터 다 받지 말고, 실제 사용 맥락에서 추가 정보를 받는 구조가 좋다.

### A. 카메라 권한

- 시점: 첫 영상 분석 시작 직전
- 카피: `자세 분석을 위해 카메라 접근이 필요해요`
- 이유: 첫 실행 직후 요청보다 훨씬 설득력 있음

### B. 알림 권한

- 시점: 첫 기록 저장 이후
- 카피: `다음 등반 리마인드와 분석 완료 알림을 받아볼까요?`
- 이유: 사용자가 가치를 본 뒤 opt-in 확률이 높아짐

### C. 심화 프로필

- 시점: 2~3회 사용 후
- 항목: 선호 홀드 타입, 약한 동작, 자주 실패하는 구간, 부상 이력
- 이유: 초반에는 과하지만, 추천 정밀도를 위해 후반 수집 가치가 큼

### D. 유료 전환

- 시점: 최소 1회 분석 또는 2회 이상 기록 후
- 메시지: `당신의 분석 기록이 쌓이기 시작했어요. PRO에서 더 자세히 볼 수 있어요`
- 이유: 피그마 섹션처럼 온보딩 중간 결제 유도는 DDGo 첫 경험에선 이르다

## 6. DDGo 비주얼 방향

피그마의 화이트 기반, 큰 타이포, 강한 CTA는 유지하되 DDGo는 아래 방향이 더 맞다.

### 비주얼 콘셉트

- 기본 배경: `chalk white`
- 본문 텍스트: `graphite black`
- 포인트 컬러: `route blue`
- 보조 포인트: 네온 퍼플보다 `lime / coral / hold yellow`를 제한적으로 사용

### 화면 인상

- 헬스 앱 느낌보다 `클라이밍 짐의 공기`, `초크 파우더`, `컬러 홀드`, `문제 테이프`가 느껴져야 함
- 배경은 완전 플랫 화이트보다 상단의 미세한 그라디언트와 초크 입자 질감이 더 좋음

### 타이포

- 헤드라인은 32~36sp급 강한 볼드
- 한 화면에 문장 1개만 크게
- 서브카피는 16sp 전후, 2줄 이내

### CTA

- 하단 고정 풀폭 버튼
- 높이 56~60dp
- 활성/비활성 차이 명확
- 버튼 레이블은 최대 8자 내외

### 선택 카드

- radius 20~24dp
- 기본은 white / stroke / very soft shadow
- 선택 시 tinted fill + accent border + icon 강조

## 7. 카피 톤앤매너

권장 톤:

- 코치처럼 도와주되 과장하지 않기
- "데이터", "분석", "기록"을 어렵게 말하지 않기
- 초보자도 부담 없는 문장

좋은 예:

- `오늘부터 내 등반 기준점을 만들어볼게요`
- `윙스팬을 알면 리치 분석이 더 정확해져요`
- `먼저 자주 가는 암장부터 알려주세요`

피해야 할 예:

- `혁신적인 AI가 당신의 실력을 극대화합니다`
- `반드시 입력하세요`
- `지금 결제해야 더 정확합니다`

## 8. 구현 우선순위

1. Hero 화면 전면 교체
2. Home Gym 선택 화면 리디자인
3. 레벨/목표 화면 추가
4. 신체 프로필 입력 화면을 한 화면 폼으로 재구성
5. 결과 카드 화면 추가
6. 카메라/알림 권한을 맥락형 요청으로 이동
7. 결제 유도는 온보딩 이후로 이관
