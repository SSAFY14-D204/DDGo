# DDGo Pose Landmarker 데이터 구조 및 활용 가이드

Pre-Pose 분석을 통해 생성되는 데이터의 구조와 이를 활용하여 정체 지점, 추락 지점 등을 계산하는 방법을 설명합니다.

## 1. 데이터 구조 (Data Structure)

분석 결과는 `List<DebugPoseFrameResult>` 형태로 반환됩니다. `OptimizedPrePoseVideoAnalyzer`는 비디오 전체를 스캔하므로, 최종 데이터는 다음과 같이 **개별 프레임 객체들이 타임스탬프 순으로 정렬된 리스트(Array)** 형태가 됩니다.

### 비디오 모드 전체 데이터 구조 (JSON Array)
```json
[
  {
    "pose": {
      "frameTimeMs": 0,
      "landmarks": [{ "index": 0, "x": 0.5, "y": 0.3, "z": -0.1 }, "..."]
    },
    "worldLandmarks": [{ "index": 0, "x": 0.0, "y": -0.5, "z": -0.2 }, "..."],
    "capturedBitmap": null
  },
  {
    "pose": {
      "frameTimeMs": 33,
      "landmarks": [{ "index": 0, "x": 0.51, "y": 0.31, "z": -0.1 }, "..."]
    },
    "worldLandmarks": [{ "index": 0, "x": 0.01, "y": -0.51, "z": -0.21 }, "..."],
    "capturedBitmap": null
  },
  {
    "pose": {
      "frameTimeMs": 5000,
      "landmarks": [{ "index": 0, "x": 0.52, "y": 0.32, "z": -0.1 }, "..."]
    },
    "worldLandmarks": [{ "index": 0, "x": 0.02, "y": -0.52, "z": -0.22 }, "..."],
    "capturedBitmap": "Binary/Base64 Image Data (5초 간격 캡처 시 존재)"
  }
]
```

### 상세 필드 설명

#### A. `Pose` (화면 정규화 좌표)
- **프레임 정보**: `frameTimeMs`는 비디오의 **시작 시점(0ms)을 기준**으로 한 상대적 시간입니다.
    - *예시*: 30fps 비디오의 경우, 약 33ms 단위로 증가합니다. (0, 33, 67, 100...)
    - *활용*: 두 프레임 사이의 `frameTimeMs` 차이를 이용하여 신체의 이동 속도($m/s$)를 계산할 수 있습니다.
- **좌표 특성**: `x, y, z`는 **0.0 ~ 1.0** 사이의 값입니다.
- **Y축 방향**: 상단이 `0`, 하단이 `1`입니다. (클라이밍 추락 시 Y값이 1에 가까워짐)

#### B. `World Landmarks` (물리 3D 좌표)
- **단위**: **미터(m)** 단위의 실제 거리 데이터입니다.
- **기준점**: 골반(Hips) 중앙을 `0,0,0`으로 잡고 신체의 실제 움직임을 계산합니다.
- **용도**: 실제 이동 거리 계산이나 물리 시뮬레이션 연동 시 필수적입니다.
- **유효성 및 오차 범위**:
    - **신뢰도**: 사람이 카메라를 정면으로 바라보고 전신이 잘 보일 때 가장 정확합니다.
    - **오차**: 실제 줄자로 잰 것 같은 절대적인 정밀도(mm 단위)를 제공하지는 않지만, **상대적인 변화량(추락 거리, 속도)**을 측정하기에는 충분히 유효합니다.
    - **주의사항**: 카메라와의 거리나 렌즈 왜곡에 따라 오차가 발생할 수 있으므로, 단일 프레임의 값보다는 여러 프레임의 **평균 변화율(Velocity)**을 사용하는 것이 안정적입니다.

## 2. 분석 알고리즘 가이드

### A. 정체 지점 (Stagnation) 계산
클라이머가 특정 구역에서 오래 머무는 상태를 감지합니다.
1.  **중심점 설정**: 엉덩이 중앙(Index 23, 24의 평균) 또는 어깨 중앙을 신체 중심점으로 사용합니다.
2.  **이동 속도 계산**: 
    - `속도 = 거리(P2 - P1) / 시간(t2 - t1)`
3.  **임계값 필터링**: 일정 시간($\Delta t$) 동안 평균 속도가 특정 임계값 이하로 유지되면 해당 구간을 '정체 구간'으로 플래그합니다.

### B. 추락 지점 (Fall) 계산
급격한 하강 움직임을 감지합니다.
1.  **Y좌표 모니터링**: 신체 중심점의 Y값 변화율을 감시합니다.
2.  **추락 감지**: 
    - **정규화 좌표계**: Y값이 짧은 시간 안에 0.8 -> 1.0 처럼 급격히 커질 때.
    - **World 좌표계**: Y축 속도가 급격하게 음수(아래 방향)로 커질 때.
3.  **지표**: `(Y_now - Y_prev) / (t_now - t_prev)` 값이 특정 수치를 넘어가면 추락으로 판정합니다.

## 3. MediaPipe 랜드마크 주요 인덱스
참고를 위해 주로 사용되는 인덱스 번호입니다:
- `0`: 코 (Nose)
- `11, 12`: 왼쪽/오른쪽 어깨 (Shoulders)
- `23, 24`: 왼쪽/오른쪽 엉덩이 (Hips) -> **클라이밍 무게중심 계산 시 유용**
- `27, 28`: 왼쪽/오른쪽 발꿈치 (Heels) -> **발 홀드 사용 여부 판단**
- `15, 16`: 왼쪽/오른쪽 손목 (Wrists) -> **손 홀드 접근 판단**
